# VisionCommand AI v0.5.0

## Release Theme

VisionCommand AI v0.5.0 expands the project from a deployed AI media demo into a more complete full-stack AI workflow platform.

This release focuses on intelligent command planning, prepared command execution, advanced zoom workflows, generated output history, workflow persistence, workflow lineage, analytics, and human-readable reporting.

The main product story is now stronger:

Upload or generate media, run command-based AI/CV actions, reuse generated outputs as new inputs, trace the workflow, inspect lineage, analyze activity, and export workflow reports.

## Why This Release Matters

v0.4.0 proved that VisionCommand AI could be deployed publicly with a working cloud demo.

v0.5.0 turns the project into a more professional AI assistant workflow system.

The project now demonstrates:

- LLM-style command planning
- Prepared command execution
- Computer vision workflow chaining
- Generated output reuse
- Workflow persistence
- Backend workflow lineage APIs
- Frontend workflow detail views
- Workflow analytics
- Human-readable workflow report export
- Stronger MLOps, LLMOps, analytics engineering, and product storytelling

This release is especially important for positioning the project toward AI Engineer, Computer Vision Engineer, Applied AI Developer, Full-stack AI Developer, MLOps Engineer, LLMOps Engineer, Data Engineer, Analytics Engineer, and Evaluation Engineer roles.

## Highlights

### 1. Intelligent Command Planning

This release adds a structured command planner layer that moves the project beyond simple rule-based command execution.

The planner work includes:

- Rule-based command planner schema and service
- `POST /commands/plan`
- Planner modes for `rule_based`, `llm_mock`, and `real_llm`
- Planner prompt builder
- Planner prompt preview endpoint
- Real LLM planner support
- Strict JSON validation for LLM planner output
- Planner evaluation and comparison endpoints
- Planner comparison visibility in the frontend
- Planner evaluation added to the LLMOps dashboard

This makes the project more relevant to LLM Engineer, Applied AI Developer, AI Engineer, and Evaluation Engineer roles.

### 2. Prepared Command Execution

The release adds a safer bridge between command planning and actual media execution.

Prepared execution includes:

- `POST /commands/plan/prepare-execution`
- Prepared command preview in the frontend
- `POST /commands/execute-prepared`
- Frontend support for executing prepared commands
- Result routing to the existing visual result panels
- Support for prepared detection, annotation, crop, blur, blur-all, extract frames, tracking preparation, and zoom-by-class workflows

This gives the project a more production-like AI tool execution flow.

### 3. Zoom-by-Class and Target-Aware Zoom

This release significantly improves the zoom workflow.

Zoom work includes:

- Backend zoom-by-class command support
- Frontend zoom result panel
- Aspect-ratio-preserving zoom output
- Zoom strength control
- Target-aware zoom execution
- Target scope support for best, largest, left, right, center, and single
- Zoom comparison view
- Ability to run YOLO on zoomed output images
- Source-aware crop and blur actions from generated zoom outputs

This strengthens the computer vision and visual editing story of the project.

### 4. Generated Output History

A major part of v0.5.0 is the Generated Output History system.

The release adds:

- Generated Output History panel
- Generated output thumbnail gallery
- Output cards for detection, zoom, crop, and blur results
- Generated output lineage display
- Grouping by workflow source filename
- Auto-use latest generated output as active image
- Rich output metadata
- Compact card layout
- Search and filtering by filename, command, label, source, action, created-by value, parser mode, and planner mode
- Workflow JSON export

Generated outputs are now treated as first-class workflow artifacts, not temporary files.

### 5. Generated Output Reuse

Generated outputs can now become new workflow inputs.

This includes:

- Run YOLO directly from generated output history cards
- Use generated outputs as the active image source
- Run detection, crop, blur, blur-all, and zoom commands against generated outputs
- Preserve source information when generated outputs are used in later actions
- Restore generated output history from workspace snapshots

This creates a real iterative AI media workflow.

### 6. Generated Output Persistence and Observability

The release adds backend persistence for Generated Output History using the existing PostgreSQL-compatible database service pattern.

Persistence and observability includes:

- `GET /db/generated-outputs`
- `POST /db/generated-outputs`
- `DELETE /db/generated-outputs`
- `DELETE /db/generated-outputs/{output_id}`
- Safe fallback behavior when `DATABASE_URL` is not configured
- Frontend Load Saved History action
- Backend clear/remove wiring
- `generated_outputs_count` in database stats
- Generated outputs shown in the frontend Database Stats card

This strengthens the backend, data engineering, and MLOps story.

### 7. Backend Workflow and Lineage APIs

This release adds backend workflow intelligence for persisted generated outputs.

New endpoints:

- `GET /db/generated-outputs/workflows`
- `GET /db/generated-outputs/source/{source_filename}`
- `GET /db/generated-outputs/{output_id}/lineage`

These APIs make generated output history queryable as workflow data.

This prepares the project for richer dashboards, workflow replay, report generation, and analytics features.

### 8. Workflow Detail View

The frontend now includes a compact workflow detail view for Generated Output History groups.

The view includes:

- View Workflow Details / Hide Workflow Details toggle
- Workflow source filename
- Ordered workflow steps
- Step action and label
- Output filename
- Command or result metadata
- Created-by value
- Parser mode
- Planner mode
- Timestamp

This makes the generated output chain understandable inside the UI.

### 9. Workflow Analytics Dashboard

The Generated Output History panel now includes workflow analytics.

Analytics includes:

- Visible output count
- Total output count
- Workflow source count
- Action type count
- Latest output
- Action distribution
- Source breakdown
- Created-by breakdown
- Parser usage
- Planner usage
- Filter-aware analytics values
- Filtered view badge

This connects the project to analytics engineering, MLOps observability, and LLMOps monitoring.

### 10. Workflow Report Export

This release adds a human-readable Markdown workflow report export.

The report includes:

- Report timestamp
- Summary
- Analytics
- Active generated image source
- Workflow groups
- Step-by-step output details
- Lineage-style source-to-output explanation

This gives the project a stronger demo and portfolio story because workflows can now be exported as readable reports, not only raw JSON.

### 11. Workspace and UX Improvements

This release also includes multiple frontend workflow improvements:

- Collapsible floating Workspace Quick Jump
- Generated output history restoration from workspace snapshots
- Per-item remove actions
- Clear history behavior improvements
- Compact Generated Output History cards
- Better generated output grouping
- Improved workflow navigation and visual traceability

These changes make the app easier to use during long AI media sessions.

- Some workflow analytics are currently frontend-calculated from available generated output history.
- PDF report export is not included yet.
- Real LLM behavior still depends on provider configuration and availability.
- Video tracking remains a future area for deeper development.
